# Tweakopedia: архитектурная спецификация

Дата: 2026-10-08  
Статус: утверждена пользователем
Название: Tweakopedia

## 1. Назначение

Tweakopedia — персональное portable-приложение для Windows 10 и Windows 11 x64, объединяющее русскоязычную офлайн-энциклопедию и декларативный твикер.

Программа должна помогать понять устройство Windows, показать фактическое состояние параметров, сформировать очередь осознанных изменений, сохранить исходное состояние, применить пакет и проверить результат. Отсутствующий или неподдерживаемый параметр не скрывается: программа объясняет причину недоступности.

Первичным источником материала служит аудит Windows 11 by SanLex и внешнего твик-пака, но продукт не привязан к этой сборке. Каждый параметр проверяется отдельно и описывается применительно к обычным сборкам Windows.

## 2. Цели

- Работать полностью автономно после распаковки portable-комплекта.
- Поддерживать Windows 10 и Windows 11 x64 разных сборок и редакций.
- Объяснять практический смысл параметров понятным русским языком.
- Определять текущее состояние до добавления изменения в очередь.
- Применять только предварительно показанный пакет операций.
- Автоматически сохранять фактическое исходное состояние каждого затрагиваемого объекта.
- Поддерживать отмену транзакции и отдельный возврат известных штатных значений Windows.
- Показывать зависимости, конфликты, перекрытия и требования перезапуска.
- Позволять добавлять контент через YAML и Markdown без перекомпиляции.
- Развиваться малыми автономными частями, каждая из которых заканчивается работающим и проверяемым результатом.

## 3. Вне области проекта

- ARM64 и x86.
- Windows старше Windows 10.
- Установщик и системная служба.
- Облачный аккаунт, синхронизация и серверная часть.
- Автоматическое обновление программы или контента.
- Телеметрия приложения.
- Загрузка удалённых сценариев и исполняемых файлов.
- Встроенный редактор пользовательских твиков.
- Обещание полностью вернуть всю Windows к исходному состоянию одной кнопкой.
- Автоматические режимы вида «максимальная оптимизация», скрывающие состав изменений.

## 6. Архитектура процессов

### 6.1 Основной процесс

`Tweakopedia.exe` работает без постоянного повышения прав. Он отвечает за:

- загрузку и проверку контента;
- определение системы через операции чтения;
- каталог, поиск, справочник и глоссарий;
- очередь, зависимости, конфликты и предварительный итог;
- хранение истории и отображение результатов;
- формирование типизированного плана для Executor.

### 6.2 Executor

`Tweakopedia.Executor.exe` запускается через UAC только при применении, отмене или возврате штатных значений. Он:

- повторно проверяет формат и допустимость плана;
- проверяет, что исходное состояние не изменилось после предварительного анализа;
- создаёт снимки;
- выполняет типизированные операции;
- проверяет результат каждой операции;
- выполняет автоматический возврат при ошибке;
- записывает структурированный результат и завершает работу.

Executor не принимает произвольный PowerShell/CMD-текст из YAML. Редкие внешние команды оформляются как заранее реализованные и разрешённые типы операций с фиксированными параметрами.

### 6.3 Поток данных

```text
Контент → профиль ОС → обнаружение состояний → каталог
       → очередь → зависимости и конфликты → предварительный план
       → снимок → Executor → проверка → история/возврат
```

## 8. Модель контента

### 8.1 Типы элементов

1. `setting` — устойчивый параметр с одним или несколькими конечными состояниями.
2. `action` — одноразовая операция без постоянного переключателя.
3. `diagnostic` — проверка без внесения изменений.

### 8.2 Основные поля твика

```yaml
id: network.dns.disable-mdns
title: Отключить mDNS
category: network
subcategory: name-resolution
kind: setting

summary: Краткое объяснение для списка.

explanation:
  purpose: Для чего Windows использует этот механизм.
  mechanism: Как он работает.
  effect: Что практически изменится.
  tradeoffs: Какие функции могут быть затронуты.
  recommendation: Когда настройка имеет смысл.
  technical_details: Какие системные объекты изменяются.

compatibility:
  architectures: [x64]
  os: [windows10, windows11]
  min_build: 19041
  required_components: [Dnscache]

states:
  enabled: {}
  disabled: {}

windows_defaults:
  - os: windows10
    builds: [19041, 19045]
    state: enabled
  - os: windows11
    builds: [22000, 26100]
    state: enabled

detect: {}
dependencies: []
conflicts: []
restart: service
impact: medium
reversibility: reversible
requires_network: false
```

У определения есть только постоянный уникальный `id`. Отдельной версии твика, ссылки на статью и списка источников нет.

### 8.3 Правила контента

- ID не меняется после появления твика.
- Объяснение хранится в том же YAML, что и реализация.
- Один ID может содержать разные реализации для диапазонов сборок.
- Отсутствующий компонент означает `unsupported`, а не `disabled`.
- Несогласованные низкоуровневые значения дают состояние `mixed`.
- Неизвестное штатное значение обозначается явно и не угадывается.
- Markdown допускается внутри объяснений и отдельных учебных материалов.
- Markdown не содержит исполняемого кода.
- Все медиафайлы локальны.
- Текст строится от практического смысла к техническим деталям.

## 9. Профиль Windows и совместимость

Профиль системы содержит:

- Windows 10 или Windows 11;
- номер сборки и UBR;
- редакцию;
- архитектуру x64;
- Windows Features и Capabilities;
- установленные AppX-пакеты;
- доступные службы и задачи;
- параметры загрузки;
- наличие требуемых устройств и компонентов;
- признаки внешнего управления политиками.

Совместимость оценивается по фактическим признакам, а не только по номеру сборки. Если сборка неизвестна, но требуемые объекты присутствуют и декларация допускает диапазон, обнаружение состояния разрешено. Изменение разрешается только при полном совпадении условий конкретной реализации.

Параметры, управляемые доменом, MDM либо другой внешней политикой, по умолчанию доступны только для чтения. Принудительное изменение требует отдельного режима и не входит в первый вертикальный срез.

## 10. Состояния и штатные значения

Общие состояния:

- `enabled`;
- `disabled`;
- `custom`;
- `mixed`;
- `unsupported`;
- `unknown`;
- специальные именованные состояния конкретного твика.

Штатные значения задаются диапазонами ОС и сборок. При отсутствии точной декларации программа показывает `windows_default_unknown` и не предлагает угадываемый возврат.

Возврат имеет два независимых режима:

1. **Отменить транзакцию** — восстановить фактические значения, сохранённые перед применением.
2. **Вернуть штатное состояние Windows** — применить известную базовую конфигурацию для текущей ОС.

Штатный возврат доступен для одного твика, категории либо выбранного набора через очередь.

## 13. Очередь и планирование

Очередь хранит `tweak id + target state`, а не готовые команды. При каждом открытии и перед применением план пересчитывается по фактическому состоянию.

Для каждого пункта показываются:

- исходное и выбранное состояние;
- уровень вмешательства;
- зависимости и конфликты;
- обратимость;
- требуемый перезапуск;
- изменяемые системные объекты.

Типы отношений:

- жёсткий конфликт — применение заблокировано;
- мягкий конфликт — требуется явное подтверждение;
- дублирование — одинаковое изменение объединяется;
- перекрытие — разные операции над одним объектом требуют разрешения;
- зависимость — добавляется автоматически и удаляется вместе с зависимым твиком.

Именованные наборы входят в первую версию. Они содержат ID и конечные состояния, но не кэшируют команды. Перед запуском набор полностью анализируется заново.

## 14. Типизированные операции

Движок должен поддерживать:

- чтение, запись и удаление значений реестра;
- создание и удаление ветвей реестра;
- конфигурацию и управление службами;
- создание, изменение, включение, выключение и удаление задач;
- Windows Features и Capabilities;
- AppX для пользователя и provisioned packages;
- BCD;
- схемы электропитания;
- сетевые параметры;
- копирование, перемещение и удаление файлов;
- управление процессами;
- ограниченные встроенные maintenance-операции.

Каждая операция определяет:

- способ чтения текущего состояния;
- формат снимка;
- применение;
- проверку результата;
- возврат;
- уровень обратимости;
- требование перезапуска.

Удаление приложений представлено отдельным разделом каталога. При первом открытии
список не строится автоматически: показывается экран с лупой, пояснением
«Нажмите на поиск, чтобы автоматически определить установленные приложения» и
кнопкой «Поиск». Во время сканирования кнопка блокируется и рядом работает
индикатор. После завершения отображаются только обнаруженные пакеты в виде
действий «Удалить <Название приложения>». Результат хранится в памяти до
обновления каталога.

## 15. Транзакции

Каталог транзакции:

```text
%LocalAppData%\Tweakopedia\transactions\<transaction-id>\
├── plan.json
├── before.json
├── operations.log
├── result.json
└── backup\
```

Порядок:

1. повторное обнаружение состояния;
2. проверка совместимости и отношений;
3. построение окончательного порядка;
4. снимок исходного состояния;
5. запуск Executor;
6. последовательное применение;
7. проверка каждой операции;
8. итоговая проверка твиков;
9. запись результата и требований перезапуска.

Операции выполняются в фазах:

1. реестр и политики;
2. службы и задачи;
3. Features, Capabilities и AppX;
4. BCD, питание и сеть;
5. файлы;
6. одноразовые и необратимые действия.

## 16. Политика ошибок и возврата

Классы обратимости:

- `reversible` — полный автоматический возврат;
- `conditional` — возврат возможен только после успешной предварительной проверки;
- `irreversible` — автоматический возврат невозможен.

На первой ошибке пакет останавливается. Уже выполненные обратимые операции возвращаются в обратном порядке. Условные операции возвращаются только при подтверждённой возможности. Необратимые операции размещаются в конце плана.

Прерванная транзакция обнаруживается при следующем запуске и показывается на «Обзоре». Пользователь получает вариант продолжить проверку либо выполнить доступный возврат.

## 17. История

История показывает:

- дату и имя пакета;
- перечень твиков и состояний;
- исходные значения;
- выполненные операции;
- ошибки;
- результат проверки;
- требования перезапуска;
- доступность полной или частичной отмены.

Транзакции можно переименовывать, фильтровать и экспортировать. Резервные копии удаляются вручную либо по явно настроенному сроку хранения.

## 18. Диагностика

Диагностика не меняет систему и проверяет:

- целостность контента;
- наличие компонентов;
- состояние служб и задач;
- противоречивые политики;
- незавершённые транзакции;
- необходимость перезагрузки;
- отличия от известной базовой конфигурации.

Отчёт экспортируется в JSON и автономный HTML.

## 19. Автономность

Программа не выполняет сетевые запросы для контента, аналитики или обновлений. Твики, которым нужен интернет для штатных механизмов Windows, имеют метку `requires_network` и отдельное подтверждение.

Tweakopedia не скачивает сценарии, DLL, EXE, AppX или другие исполняемые материалы. Операции, основанные на удалённых сторонних файлах, не включаются в каталог.

## 20. Журналирование данных

В обычный журнал не включаются:

- пароли;
- ключи продуктов;
- содержимое приватных пользовательских файлов;
- секретные значения реестра.

Для чувствительных снимков фиксируются факт создания, тип объекта, путь резервной копии и контрольная сумма. Сами данные остаются только в каталоге транзакции с ограниченными правами доступа.

- интеграционные тесты Windows 11 x64.

### 21.3 Правило вертикальных срезов

Каждый этап должен завершаться функцией, которую можно запустить и проверить. Нельзя откладывать соединение интерфейса, доменной модели и backend до конца разработки.

## 23. Критерии первого пригодного вертикального среза

Первый вертикальный срез считается готовым, когда приложение:

- запускается из portable-каталога;
- определяет Windows 10/11 x64 и номер сборки;
- загружает один реальный YAML-твик реестра;
- показывает его в каталоге;
- определяет текущее состояние;
- открывает объяснение через `?`;
- добавляет изменение в очередь;
- показывает предварительный план;
- запускает Executor;
- сохраняет исходное значение;
- применяет и проверяет изменение;
- показывает транзакцию в истории;
- полностью возвращает исходное значение.

Этот срез должен быть реализован тестами до расширения количества типов операций и контента.

## 24. Принятые решения

- Программа личная, но архитектура универсальна для разных сборок Windows.
- Windows 10/11 x64; ARM64 не поддерживается.
- Только portable-поставка.
- C++20 + Qt 6 + QML/Qt Quick.
- Декларативный движок, сценарии не являются основным механизмом.
- Основной процесс не работает постоянно с повышенными правами.
- Применение выполняется только через очередь и итоговый план.
- Перед каждым пакетом сохраняется фактическое состояние.
- Имеются отмена транзакции и отдельный возврат штатных значений.
- Встроенного редактора твиков нет.
- Объяснение находится внутри YAML; библиография не ведётся.
- Именованные наборы входят в первую версию.
- Программа не выполняет собственные сетевые загрузки.

# Tweakopedia: Fluent UI и единый EXE-контейнер

Дата: 2026-10-08  
Статус: дизайн утверждён в диалоге, ожидает проверки спецификации пользователем

## 1. Контекст

Первый вертикальный срез подтвердил доменную модель, очередь, предварительный
план, транзакционный Executor и возврат изменений. Его интерфейс использует
стандартное оформление Qt Quick Controls и служит функциональным каркасом.
Текущая оболочка визуально не соответствует Windows 11: верхние вкладки плохо
масштабируются, двоичное состояние выбирается выпадающим списком, выбранные
изменения недостаточно заметны, а панель пояснения может получить некорректные
цвета из платформенной палитры.

Новая оболочка должна повторять визуальный язык светлой версии
[UCC-Revorked](https://github.com/noteMASTER11/UCC-Revorked), оставаясь
самостоятельной реализацией на Qt Quick. Базовые правила берутся из
[Fluent 2](https://fluent2.microsoft.design/) и рекомендаций Windows для
[NavigationView](https://learn.microsoft.com/en-us/windows/apps/design/controls/navigationview).

Одновременно формат поставки меняется с portable-каталога на один
распространяемый `Tweakopedia.exe`. Qt остаётся динамически подключаемым:
нативный загрузчик извлекает внутренний portable-комплект в версионированный
локальный кэш.

## 2. Цели

- Светлая Fluent 2-оболочка, визуально согласованная с UCC-Revorked.
- Адаптивная левая навигация вместо верхних вкладок.
- Бинарные твики управляются тогглами.
- Выбранное, но ещё не применённое изменение однозначно видно в строке.
- Фактическое и планируемое состояния не смешиваются.
- Пояснение по `?` остаётся рядом с рабочим контекстом.
- Release распространяется одним EXE-файлом.
- Повторный запуск использует уже распакованный runtime-кэш.
- Старые неиспользуемые версии runtime удаляются автоматически.
- Существующие очередь, preview, транзакции, повышение прав и возврат
  сохраняют текущую семантику.

## 3. Вне объёма этой итерации

- Тёмная тема.
- ARM64.
- Редактор пользовательских твиков.
- Мгновенное применение твика непосредственно тогглом.
- Установщик, системная служба или запись программы в Program Files.
- Перенос исходного кода Fluent-компонентов из UCC-Revorked.
- Переработка формата YAML и исполнительного протокола без необходимости,
  вызванной новой оболочкой или контейнером.

## 4. Выбранное визуальное направление

Используется второй из трёх согласованных макетов: компактный рабочий экран с
основной левой навигацией, отдельной колонкой категорий, плотным списком
параметров и нижней командной панелью очереди.

На широком окне структура выглядит так:

```text
┌──────────────┬──────────────┬──────────────────────────────────────────┐
│ Навигация    │ Категории    │ Заголовок, поиск и фильтры               │
│ приложения   │ твиков       ├──────────────────────────────────────────┤
│              │              │ Строки твиков                            │
│              │              │                                          │
│ Настройки    │              ├──────────────────────────────────────────┤
│              │              │ Очередь: N          Проверить и применить │
└──────────────┴──────────────┴──────────────────────────────────────────┘
```

При открытом пояснении справа появляется панель шириной около 420 px. На
широком окне она сужает список, на узком — выезжает поверх него.

## 5. UI Kit

Приложение переключается на `QtQuick.Controls.Basic`. Все продуктовые
контролы оформляются собственными QML-компонентами, чтобы результат не зависел
от старого платформенного стиля Qt.

### 5.1. Токены светлой темы

| Токен | Значение | Назначение |
|---|---:|---|
| `canvas` | `#F7F8FC` | фон окна и страниц |
| `surface` | `#FFFFFF` | карточки, строки и панели |
| `surfaceInset` | `#F4F6FA` | вложенные блоки |
| `textPrimary` | `#20232B` | основной текст |
| `textSecondary` | `#687487` | пояснения и метаданные |
| `stroke` | `#E1E5ED` | обычные границы |
| `accent` | `#0067C0` | выбранная навигация и основные команды |
| `accentHover` | `#005BAA` | hover основной команды |
| `hover` | `#F2F5FA` | hover нейтральной поверхности |
| `selected` | `#DEE9FB` | выбранная навигация и изменённая строка |
| `disabledSurface` | `#F5F6F8` | недоступные элементы |
| `disabledText` | `#9299A6` | текст недоступных элементов |
| `stateOn` | `#107C10` | слово `включено` |
| `stateOff` | `#C42B1C` | слово `выключено` |
| `stateUnknown` | `#687487` | неизвестное состояние |

Цвет состояния никогда не используется без текстового названия состояния.

### 5.2. Геометрия и типографика

- Основной шрифт: `Segoe UI`, затем системный sans-serif fallback.
- Заголовок страницы: 28 px, semibold.
- Заголовок раздела: 20 px, semibold.
- Название твика: 15–16 px, semibold.
- Основной текст: 14 px.
- Метаданные: 12 px.
- Базовый шаг отступов: 4 px; рабочие значения 8, 12, 16, 20 и 24 px.
- Радиус карточек и панелей: 8 px.
- Радиус кнопок и полей: 4–6 px.
- Граница: 1 px; у выбранной строки слева добавляется полоса 3 px.
- Тени используются только для всплывающих и выезжающих поверхностей.

### 5.3. Компоненты

- `FluentTheme`: singleton с семантическими токенами.
- `FluentNavigation`: основная адаптивная навигация.
- `FluentNavigationItem`: иконка, подпись, выбранное состояние и счётчик.
- `CategoryRail`: список категорий твиков.
- `FluentToggle`: двоичный параметр с полным кликабельным полем.
- `StateLabel`: префикс и выделенное состояние.
- `TweakRow`: строка параметра и все её состояния.
- `InfoButton`: кнопка `?` с доступным именем.
- `InfoPane`: пояснение и сворачиваемые технические сведения.
- `QueueCommandBar`: постоянная нижняя панель очереди.
- `FluentBadge`: компактная метка состояния или требования перезапуска.
- `FluentSearchField`: поиск по каталогу.

Нативная рамка Windows и системные кнопки окна сохраняются. Светлое оформление
заголовка задаётся через Windows API; собственная подмена рамки на QML не
вводится.

## 6. Навигация и адаптация

Основные пункты:

1. Обзор.
2. Твики.
3. Справочник.
4. Очередь.
5. История.
6. Настройки — закреплены снизу.

Поведение по ширине:

- от 1100 px: основная панель развёрнута до 220 px;
- менее 1100 px: панель сжимается до 64 px, подписи заменяются подсказками;
- категории на широком окне занимают отдельную колонку;
- на узком окне категории становятся горизонтальной прокручиваемой строкой;
- панель пояснения становится overlay-панелью;
- минимальный размер окна остаётся пригодным для очереди и preview.

Счётчик очереди показывается возле пункта `Очередь` и в нижней командной
панели. Значение берётся из одной модели и не дублируется локальным состоянием
QML.

## 7. Строка бинарного твика

Тоггл показывает желаемое состояние, но не изменяет Windows немедленно.
Фактическое состояние всегда выводится отдельной строкой.

### 7.1. Визуальная семантика

- `Сейчас:` — обычный `textSecondary`.
- `выключено` — semibold, `stateOff`.
- `включено` — semibold, `stateOn`.
- `не определено` — semibold, `stateUnknown`.
- При наличии цели появляется строка `После применения:` с теми же правилами.
- Изменённая строка получает фон `selected`, полосу `accent` слева и метку
  `Изменено`.
- Возврат тоггла к фактическому состоянию удаляет твик из очереди и возвращает
  нейтральное оформление.
- Неподдерживаемая строка остаётся видимой, но тоггл недоступен; причина
  выводится текстом.

### 7.2. Таблица состояний

| Фактическое | Цель | Тоггл | Подсветка | Текст |
|---|---|---:|---:|---|
| выключено | отсутствует | off | нет | `Сейчас: выключено` |
| выключено | включено | on | да | `Сейчас: выключено`; `После применения: включено` |
| включено | отсутствует | on | нет | `Сейчас: включено` |
| включено | выключено | off | да | `Сейчас: включено`; `После применения: выключено` |
| неизвестно | отсутствует | disabled | нет | `Сейчас: не определено` и причина |

Для будущих параметров с тремя и более состояниями остаются сегментированные
кнопки или селектор. Требование тоггла относится только к строго бинарным
параметрам.

## 8. Пояснение по вопросительному знаку

`InfoButton` открывает `InfoPane` для выбранного твика. Панель содержит:

1. Название и краткое назначение.
2. Механизм.
3. Эффект.
4. Ограничения.
5. Рекомендацию.
6. Сворачиваемый раздел `Технические сведения`.
7. Объект реестра или другой системный объект.
8. Способ возврата.

Панель не меняет очередь. Повторный выбор другого `?` заменяет содержимое без
закрытия панели. `Esc` закрывает overlay-режим и возвращает фокус вызвавшей
кнопке.

## 9. Очередь и применение

Новая оболочка не меняет утверждённый процесс:

```text
тоггл → очередь → общий итог → подтверждение → пакетное применение
```

- Тоггл вызывает `selectTarget`.
- Выбор фактического состояния вызывает удаление цели из очереди.
- Нижняя панель показывает количество изменений и кнопку
  `Просмотреть и применить`.
- Применение недоступно до пересчёта preview.
- Перед выполнением сохраняются реальные исходные значения и журнал
  транзакции.
- Ручной возврат Windows defaults остаётся отдельной будущей функцией и не
  подменяет точный возврат транзакции.

## 10. Единый распространяемый EXE

### 10.1. Состав

`dist\Tweakopedia.exe` состоит из:

1. Небольшого нативного Win32 bootstrap без зависимости от Qt.
2. Присоединённого сжатого payload.
3. Footer с magic, версией формата, смещением, размером и SHA-256 payload.

Payload содержит:

- `Tweakopedia.App.exe`;
- `Tweakopedia.Executor.exe`;
- динамические Qt DLL и плагины;
- QML-модули;
- `yaml-cpp` и прочие требуемые runtime-компоненты;
- каталог YAML;
- тексты лицензий Qt и остальных распространяемых компонентов;
- `payload-manifest.json` с относительными путями, размерами и SHA-256.

Qt продолжает использовать динамическое подключение, как рекомендует его
[Windows deployment guide](https://doc.qt.io/qt-6.5/windows-deployment.html).

### 10.2. Формат и распаковка

- Portable-комплект сначала строится в staging-каталог существующим CMake и
  `windeployqt`.
- Пакетировщик создаёт ZIP/Deflate payload с детерминированным порядком файлов.
- Bootstrap использует `miniz 3.1.2` (`miniz-3.1.2.zip`, SHA-256
  `F0446D863F9C19926AD9483C523FDC42E42B8D4A6A431D27E09D49C79A140D9A`),
  `nlohmann/json 3.12.0` (`include.zip`, SHA-256
  `B8CB0EF2DD7F57F18933997C9934BB1FA962594F701CD5A8D3C2C80541559372`)
  для строгого чтения manifest и WinAPI SHA-256 через CNG. Обе зависимости
  записываются в lock-файл сборки.
- Архив присоединяется к PE как overlay; footer расположен в конце файла.
- Окончательный SHA-256 payload является идентификатором runtime-версии.

### 10.3. Runtime-кэш

```text
%LocalAppData%\Tweakopedia\
├── Data\
│   ├── tweakopedia.db
│   ├── logs\
│   └── transactions\
└── Runtime\
    ├── <payload-sha256>\
    └── .staging-<pid>-<random>\
```

Алгоритм запуска:

1. Прочитать и проверить footer.
2. Вычислить SHA-256 payload и сравнить с footer.
3. Захватить именованный mutex, привязанный к SHA-256.
4. Если готовый кэш существует, проверить marker и manifest.
5. Иначе распаковать во staging-каталог.
6. Проверить размер и SHA-256 каждого файла.
7. Создать marker готовности и атомарно переименовать staging.
8. Запустить `Tweakopedia.App.exe`, передав runtime root и путь контейнера.
9. После успешного запуска удалить старые runtime-каталоги, если их не
   использует другой процесс.
10. Дождаться завершения GUI и вернуть его exit code.

Активный runtime удерживает lock-файл. Каталог с занятым lock не удаляется;
очистка повторяется при следующем запуске. Рядом с распространяемым EXE ничего
не создаётся.

При первом запуске новой схемы существующие `tweakopedia.db`, `logs` и
`transactions` из прежнего корня `%LocalAppData%\Tweakopedia` переносятся в
`Data` только если целевые пути ещё отсутствуют. Миграция записывает marker и
может безопасно продолжиться после прерывания: каждый объект переносится
отдельно, существующая цель не перезаписывается.
Если хотя бы один legacy-объект остаётся неперенесённым, GUI не запускается:
это исключает одновременное появление двух независимых историй в старом и
новом расположениях. После устранения конфликта следующий запуск продолжает
миграцию.

### 10.4. Executor

Разделение процессов сохраняется. GUI запускает
`Runtime\<hash>\Tweakopedia.Executor.exe` существующим путём `runas`. Оба
процесса работают с одним каталогом транзакции в `Data`. Проверка nonce,
клиентского PID, канонического плана и фактического состояния сохраняется.

### 10.5. Ошибки bootstrap

До запуска Qt сообщения показывает нативный `TaskDialog` или `MessageBox`.
Сообщение содержит этап, системный код и путь, но не выводит содержимое
пользовательских данных.

- Некорректный footer или payload: запуск прекращается.
- Неполный staging: каталог удаляется при следующей попытке.
- Повреждённый готовый кэш: переименовывается в quarantine-каталог и
  распаковывается заново.
- Занятый старый runtime: пропускается без ошибки запуска.
- Невозможность создать кэш или запустить GUI: возвращается ненулевой код.

## 11. Сборка и режим разработки

- Debug и обычная локальная разработка продолжают запускать распакованные
  `Tweakopedia.App.exe` и `Tweakopedia.Executor.exe`.
- Release pipeline сначала создаёт проверенный portable staging, затем
  упаковывает его в контейнер.
- `dist` очищается только после проверки точного канонического пути.
- Конечный `dist` содержит ровно один файл `Tweakopedia.exe`.
- Все toolchain, cache, временные build-файлы и результаты проекта остаются
  под `D:\ChatGPT`.

## 12. Проверки

### 12.1. QML и приложение

- Тоггл добавляет изменение в очередь, но не вызывает Executor.
- Возврат к фактическому состоянию удаляет изменение.
- `StateLabel` применяет правильный текст, насыщенность и семантический цвет.
- Подсветка и метка появляются только при наличии цели.
- Неподдерживаемый и неизвестный твик не создают изменение.
- Навигация переключается на compact-режим в заданной точке.
- Категории меняют колонку на горизонтальный режим.
- `InfoPane` корректно работает как dock и overlay.
- Клавиатурный фокус, `Esc`, tooltip и доступные имена проверяются тестами.
- Реальные снимки делаются при масштабах 100%, 125% и 150%.

### 12.2. Bootstrap

- Разбор корректного и повреждённого footer.
- Проверка SHA-256 payload и отдельных файлов.
- Первая распаковка через staging.
- Повторный запуск без распаковки.
- Параллельный запуск двух контейнеров.
- Восстановление после неполного staging.
- Повторная распаковка повреждённого кэша.
- Очистка старой версии и сохранение занятой версии.
- Пробелы и Unicode в пути пользователя.
- Запуск при очищенном `PATH`, без установленного Qt.

Тестовые TEMP, LOCALAPPDATA override, build и cache направляются под
`D:\ChatGPT\Temp\Tweakopedia` и `D:\ChatGPT\Cache\Tweakopedia`; системные
переменные Windows глобально не меняются.

### 12.3. Приёмочные критерии

- В `dist` находится только `Tweakopedia.exe`.
- EXE запускается офлайн на Windows 10 и Windows 11 x64 без установленного Qt.
- Первый запуск создаёт один корректный runtime-кэш.
- Второй запуск использует существующий кэш.
- Старая незанятая версия удаляется после запуска новой.
- Каталог и единственный реальный твик загружаются из payload.
- Тоггл меняет только очередь.
- Изменённая строка визуально и текстово отличается от неизменённой.
- `Сейчас: выключено` и `Сейчас: включено` используют утверждённые цвета и
  semibold.
- Preview, повышение прав, снимок исходных значений, применение, история и
  возврат проходят прежний сквозной сценарий.

## 13. Последовательность реализации

1. Зафиксировать QML screenshot harness и тесты состояний до смены UI.
2. Ввести `FluentTheme` и базовые контролы.
3. Заменить оболочку на адаптивную левую навигацию.
4. Реализовать компактную страницу твиков и новую строку.
5. Переработать `InfoPane`, очередь и остальные существующие страницы.
6. Провести визуальную проверку светлой темы в трёх масштабах.
7. Добавить нативный bootstrap и формат payload.
8. Добавить версионированный runtime-кэш и очистку.
9. Перевести release packaging на единственный EXE.
10. Повторить полный набор unit, QML, integration и package-проверок.

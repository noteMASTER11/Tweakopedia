# Проверка файловой системы — спецификация

## Назначение

Добавить в раздел «Инструменты» рабочую проверку локальных NTFS-томов средствами CHKDSK. Пользователь выбирает том, запускает проверку, видит живой вывод системной команды и получает понятный итог без изменения файловой системы.

## Границы версии

- Выполняется только `chkdsk.exe <буква>:` без `/F`, `/R`, `/X`, `/B`, `/spotfix` и других исправляющих ключей.
- Не создаются задания на перезагрузку и не отправляется интерактивный ответ CHKDSK.
- Отображаются готовые локальные NTFS-тома с буквами дисков; сетевые, оптические и неподдерживаемые файловые системы исключаются.
- Проверка запускается через существующий повышенный Executor.
- Исправление найденных проблем остаётся вне этой версии.

Microsoft указывает, что CHKDSK без параметров показывает состояние тома и не исправляет ошибки. Коды завершения интерпретируются по официальной таблице: `0` — ошибок не найдено; `2` — исправление не выполнено, поскольку `/F` не задан; `3` — том не удалось проверить либо ошибки не исправлены без `/F`. Код `1` в режиме без исправления считается неожиданным результатом и не маскируется как успешный. Источник: [chkdsk — Microsoft Learn](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/chkdsk).

## Пользовательский сценарий

1. Пользователь открывает карточку «Проверка файловой системы».
2. Экран показывает список доступных NTFS-томов. Системный том выбран первым.
3. Пользователь нажимает «Начать проверку».
4. Приложение запрашивает повышение прав и запускает `chkdsk.exe` с выбранной буквой.
5. Вывод поступает в прокручиваемый терминал и одновременно сохраняется в журнал сеанса.
6. После завершения экран показывает один из итогов:
   - файловая система исправна;
   - найдены проблемы, ничего не изменено;
   - проверка не завершена;
   - команда не запустилась или завершилась аварийно.
7. Пользователь может повторить проверку, скопировать вывод или открыть журнал сеанса.

## Интерфейс

Экран следует компоновке DISM-инструмента:

- кнопка возврата и заголовок;
- верхняя карточка с выбором тома, файловой системой, меткой, общей и свободной ёмкостью;
- карточка состояния с индикатором неопределённого прогресса во время работы;
- основная кнопка справа в широком окне и на всю ширину в узком;
- терминальная область с моноширинным шрифтом, автопрокруткой и ручной прокруткой;
- вторичные действия «Копировать вывод» и «Открыть журнал»;
- зелёное, жёлтое или красное состояние результата без предложения автоматического исправления.

Если подходящих томов нет, выбор и запуск блокируются, а экран объясняет причину. Смена тома во время выполнения блокируется. Возврат в сетку инструментов не прерывает работающую проверку.

## Архитектура

### Общий контракт инструментов

Существующий `SystemToolProtocol` становится действительно общим:

- `SystemToolKind`: `ComponentStore`, `FileSystem`;
- `SystemToolOperation`: `Scan`, `Restore`, `Check`;
- `SystemToolStage`: существующие стадии DISM плюс `CheckFileSystem`;
- `SystemToolOutcome`: `Healthy`, `Repairable`, `NonRepairable`, `IssuesFound`, `Incomplete`, `Unknown`;
- запрос содержит тип инструмента, операцию и необязательную цель;
- для CHKDSK цель обязательна и строго соответствует `^[A-Z]:$`.

IPC сохраняет UUID запроса, последовательность фрагментов и подтверждение результата. Произвольная команда через IPC не передаётся.

### Поиск томов

`WindowsLocalVolumeProvider` использует Win32-функции `GetLogicalDriveStringsW`, `GetDriveTypeW`, `GetVolumeInformationW` и `GetDiskFreeSpaceExW`. Он возвращает только доступные локальные NTFS-тома с буквами дисков и сортирует системный том первым.

### Выполнение CHKDSK

`FileSystemCheckWorkflow` получает уже проверенную цель, открывает журнал `Logs/Tools/FileSystemCheck`, запускает системный `%WINDIR%\System32\chkdsk.exe` ровно с одним аргументом `<буква>:` через общий `QProcess`-runner и передаёт необработанные байты в журнал. Экранный буфер получает нормализованные строки через инкрементальный декодер; его размер ограничен 2 МиБ, как у DISM.

Итог определяется по завершению процесса и коду CHKDSK, а не по локализованным строкам:

| Код | Итог |
|---:|---|
| 0 | `Healthy` |
| 2 | `IssuesFound` |
| 3 | `Incomplete` |
| 1 | `Incomplete` с пояснением неожиданного кода для режима чтения |
| прочие | `Failed` |

### Контроллер

`FileSystemCheckController` отвечает за список томов, выбор, запуск, 2-МиБ экранный буфер, русские итоговые тексты, копирование и открытие журнала. Общий `SystemToolSession` принимает тип инструмента, операцию и цель, поэтому DISM и CHKDSK не могут выполняться одновременно в одном экземпляре приложения.

## Отказы и пограничные случаи

- Неверная цель отвергается до запуска процесса и при декодировании IPC.
- Том, исчезнувший после выбора, приводит к понятному итоговому сообщению CHKDSK, а не к зависанию.
- Отмена UAC возвращает экран в состояние ожидания и сохраняет выбранный том.
- Потеря IPC, раннее завершение Executor и тайм-аут используют существующие механизмы `SystemToolSession`.
- Код `2` не считается аварией: это подтверждённый результат проверки без исправления.
- Локализованный вывод всегда показывается как есть; логика результата от него не зависит.

## Проверка реализации

- модульные тесты протокола и строгой проверки цели;
- модульные тесты поиска/сортировки томов через отделённый интерфейс;
- RED→GREEN тесты workflow для кодов `0`, `2`, `3`, неожиданного кода и ошибки запуска;
- тесты контроллера для выбора, UAC, состояния, ограничения буфера и действий с журналом;
- IPC-тест CHKDSK через fixture-runner без запуска реальной проверки диска;
- QML-тесты широкого и узкого экрана;
- полный CTest, Release-сборка и проверка единого EXE-контейнера.

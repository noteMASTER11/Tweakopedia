# Стартовый экран Tweakopedia

Дата: 09.10.2026

## Цель

Показывать окно Tweakopedia сразу после запуска единого EXE и объяснять
фактическую работу приложения до появления основного интерфейса. Экран следует
утверждённому варианту 1: крупный логотип, заголовок «Загрузка...», круговой
неопределённый индикатор и компактный список текущего и следующих этапов.

Проценты не отображаются: проверка файлов, чтение реестра и построение моделей
не дают устойчивой линейной шкалы.

## Причина задержки

Portable EXE сначала выполняет код нативного bootstrap без Qt:

1. проверяет footer и SHA-256 встроенного payload;
2. подготавливает локальную структуру данных;
3. проверяет либо извлекает Qt-runtime;
4. запускает `Tweakopedia.App.exe`.

Основной процесс до загрузки `Main.qml` синхронно открывает локальную базу,
загружает и проверяет каталог, определяет профиль Windows, читает фактические
значения твиков и строит модели. Поэтому обычный QML-экран не может перекрыть
всю задержку.

## Внешний вид

- Обычное окно Windows с заголовком `Tweakopedia`, иконкой приложения и
  размерами основного окна.
- Светлый фон Fluent UI.
- По центру верхней половины — полноразмерный логотип Tweakopedia.
- Ниже — заголовок `Загрузка...` и анимированный круговой индикатор.
- Под индикатором — не более трёх строк: текущий этап и два следующих.
- Текущий этап выделен синим маркером и основным цветом текста; следующие
  отображаются приглушённо.
- При смене этапа список обновляется без скачка всего центрального блока.
- Масштабирование учитывает системный DPI; текст использует `Segoe UI`.

## Архитектура

### Нативное окно bootstrap

Bootstrap создаёт стартовое Win32-окно до вызова `inspectContainer()`. Логотип
встраивается в ресурсы EXE и декодируется системными средствами Windows, без
зависимости от Qt-runtime.

Фоновые операции bootstrap выполняются в рабочем потоке. Главный поток
обслуживает очередь сообщений окна и таймер индикатора, поэтому анимация не
останавливается во время вычисления хэшей и распаковки.

Физически стартовое окно остаётся владельцем bootstrap до готовности основного
окна. Создавать второе внешне идентичное окно в Qt не требуется: это исключает
мерцание и расхождение геометрии. Для пользователя передача управления выглядит
как замена содержимого в одном месте.

### Передача статусов

Bootstrap передаёт дочернему процессу дескриптор стартового окна отдельным
аргументом командной строки. Основной процесс отправляет только известные
идентификаторы этапов через `WM_COPYDATA`. Bootstrap сопоставляет идентификатор
с русской подписью и игнорирует неизвестные сообщения.

После создания корневого QML-окна основной процесс:

1. применяет геометрию стартового окна;
2. показывает основное окно;
3. уведомляет bootstrap о готовности;
4. bootstrap скрывает стартовое окно.

Bootstrap продолжает ожидать завершения дочернего процесса, как и сейчас, чтобы
после выхода удалить устаревшие версии runtime-кэша.

### Контракт этапов

Общий тип `StartupStage` содержит стабильные идентификаторы, но не хранит
проценты. Русские подписи принадлежат слою представления стартового окна.

Фактическая последовательность:

| Этап | Реальная операция |
|---|---|
| `container_integrity` | `inspectContainer()` и проверка SHA-256 payload |
| `local_data` | миграция прежней структуры локальных данных |
| `runtime_cache` | проверка файлов текущего runtime по manifest |
| `runtime_extract` | извлечение payload, только если готового кэша нет |
| `app_launch` | создание процесса `Tweakopedia.App.exe` |
| `data_store` | создание каталогов данных, открытие SQLite и восстановление прерванных транзакций |
| `catalog_load` | загрузка YAML-твиков и `categories.yaml` |
| `catalog_validate` | проверка связей категорий и подкатегорий |
| `windows_profile` | определение семейства, сборки и архитектуры Windows |
| `state_detection` | чтение фактических значений всех поддерживаемых типов твиков |
| `models` | построение списков твиков, категорий, групп, истории и Твикопедии |
| `interface` | загрузка `Main.qml` и создание основного окна |

Подписи для пользователя:

- `Проверка целостности приложения`
- `Подготовка локальных данных`
- `Проверка локального кэша`
- `Извлечение встроенных компонентов`
- `Запуск компонентов приложения`
- `Открытие локальных данных`
- `Загрузка каталога твиков`
- `Проверка структуры каталога`
- `Определение версии Windows`
- `Определение текущих значений параметров`
- `Подготовка разделов приложения`
- `Создание интерфейса`

Этап извлечения условный и не показывается при пригодном кэше.

## Сведения о компьютере

WMI/DXGI-сведения обзора уже собираются через `QtConcurrent` после построения
моделей. Стартовый экран не ждёт их завершения. Страница «Обзор» продолжает
показывать собственный индикатор до получения результата.

## Ошибки и специальные режимы

- При ошибке bootstrap индикатор останавливается, стартовое окно скрывается и
  показывается существующий системный диалог с причиной.
- При ошибке инициализации основного процесса стартовое окно закрывается после
  отображения сообщения, а незавершённый основной интерфейс не показывается.
- Для `--self-check` стартовое окно отключается, чтобы тестовый запуск оставался
  неинтерактивным.
- Повторный запуск не использует сохранённые фиктивные статусы: каждый этап
  отправляется непосредственно перед соответствующей операцией.

## Изменения интерфейсов

- `BootstrapApplication` получает интерфейс приёмника прогресса.
- `RuntimeCache::prepare()` сообщает начало проверки и фактического извлечения.
- `WindowsBootstrapPlatform::launchAndWait()` обслуживает сообщения окна во
  время ожидания дочернего процесса.
- `AppController::startup()` получает callback этапов и вызывает его на границах
  существующих операций.
- В `main.cpp` основного приложения добавляются чтение дескриптора bootstrap,
  отправка этапов и уведомление о готовом QML-окне.

## Проверка

- Unit-тест порядка и русских подписей этапов.
- Тесты горячего кэша и первого извлечения подтверждают условный этап
  `runtime_extract`.
- Тест bootstrap подтверждает, что первый статус отправлен до проверки
  контейнера.
- Тест основного приложения подтверждает порядок загрузки каталога, определения
  состояний, построения моделей и интерфейса.
- Ручные снимки при 100%, 125%, 150% и 200% DPI.
- Проверка холодного и повторного запуска portable EXE.
- Полный CTest и повторная проверка single-EXE упаковки.

## Критерии готовности

- Стартовое окно создаётся до длительных операций bootstrap.
- Индикатор продолжает вращаться во время проверки и распаковки.
- Все показанные подписи соответствуют выполняемой операции.
- Основное окно появляется в той же геометрии без заметной вспышки второго окна.
- Сбор системного обзора не задерживает переход к основному интерфейсу.
- Portable-поставка остаётся одним EXE.

# Раздел «Твикопедия»: архитектурная спецификация

Дата: 2026-10-08

Статус: утверждена пользователем

Основа интерфейса: утверждённый Fluent UI-макет № 2

## 1. Назначение

Пустой раздел «Справочник» заменяется полноценной офлайн-энциклопедией
«Твикопедия». Каждому твик-определению из YAML соответствует статья. Пользователь
может изучать устройство Windows через дерево тем и полнотекстовый поиск, не
переходя по категориям экрана «Твики».

YAML-каталог остаётся единственным источником текста и технических сведений.
Отдельная копия статей не создаётся.

## 2. Границы первой реализации

В первую реализацию входят:

- переименование пункта навигации и замена пустой страницы;
- дерево `категория → подкатегория → статья`;
- поиск по всем текстовым и техническим полям;
- полноформатная статья из существующих YAML-данных;
- содержание статьи с переходами к разделам;
- хлебные крошки;
- история переходов назад и вперёд внутри раздела;
- автоматически вычисляемые связанные статьи;
- адаптивное представление для широкого и узкого окна.

Не входят:

- отдельный редактор статей;
- ручное назначение ссылок между статьями;
- сетевой контент;
- комментарии, закладки и синхронизация;
- собственный формат статей, дублирующий YAML;
- переход к изменению параметра непосредственно из текста статьи.

## 3. Информационная архитектура

Дерево строится из уже загруженных `CategoryCatalog` и `TweakCatalog`:

```text
Категория
└── Подкатегория
    ├── Статья, построенная из твика A
    └── Статья, построенная из твика B
```

Каждый твик создаёт ровно одну статью с тем же постоянным `id`. Категории и
подкатегории используют локализованные названия из `categories.yaml`.

Флажок «Скрыть неподдерживаемые твики» относится только к каталогу твиков и не
влияет на энциклопедию. В «Твикопедии» доступны материалы для всех описанных
версий Windows; совместимость показывается внутри статьи.

## 4. Компоновка

### 4.1 Широкое окно

- Сохраняется основная левая Fluent-навигация приложения.
- В верхней части страницы находятся кнопки назад/вперёд и строка поиска.
- Слева внутри страницы располагается дерево энциклопедии.
- Основную ширину занимает белое полотно статьи.
- Содержание статьи располагается компактной закреплённой панелью справа внутри
  полотна.
- Связанные статьи находятся внизу статьи в виде горизонтального ряда карточек.

### 4.2 Средняя ширина

- Дерево остаётся видимым, но сужается.
- Содержание статьи превращается в плавающую кнопку и открывает небольшую панель.
- Текстовые секции переходят из двух колонок в одну.

### 4.3 Узкое окно

- Основная навигация приложения переходит в существующий компактный режим.
- Дерево открывается отдельной выдвижной панелью по кнопке.
- Статья занимает всю доступную ширину.
- Связанные статьи располагаются вертикально.

Точные пороги берутся из существующего механизма адаптивной навигации, чтобы не
создавать второй набор несовпадающих брейкпоинтов.

## 5. Поиск

Поиск выполняется локально по нормализованному индексу, построенному при загрузке
каталога. Для текущего размера каталога используется индекс в памяти без новой
базы данных.

Индексируются:

- название;
- краткое описание;
- `purpose`;
- `mechanism`;
- `effect`;
- `tradeoffs`;
- `recommendation`;
- `technical_details`;
- названия категории и подкатегории;
- идентификатор твика;
- пути реестра, службы, команды и другие описанные системные объекты.

Правила выдачи:

1. точное совпадение названия;
2. совпадение начала названия;
3. совпадение слов названия;
4. совпадение краткого описания;
5. совпадение основного текста;
6. совпадение технических полей.

Во время поиска дерево фильтруется, но сохраняет родительские категории и
подкатегории найденных статей. Пустые ветви скрываются. В результатах показывается
полный путь статьи. Поиск не меняет состояние твиков и не зависит от очереди.

## 6. Конструктор статьи

Статья собирается только из доступных данных. Пустые блоки не создаются.

Порядок блоков:

1. хлебные крошки;
2. название;
3. вводный текст из `summary`;
4. информационная Fluent-плашка с кратким смыслом, если есть `purpose`;
5. «Назначение»;
6. «Как это работает»;
7. «Что изменится»;
8. «Ограничения»;
9. «Рекомендация»;
10. сворачиваемые «Технические сведения»;
11. совместимость и требуемый перезапуск;
12. «Связанные статьи».

Технический блок объединяет `technical_details`, объекты операций и описание
возврата. Длинные пути и команды переносятся, допускают выделение и используют
моноширинное начертание.

Содержание статьи строится из реально присутствующих блоков. Нажатие на пункт
прокручивает статью к соответствующему заголовку и обновляет активный пункт при
ручной прокрутке.

## 7. Связанные статьи

Связи вычисляются автоматически и не требуют нового поля в YAML. Для каждого
кандидата рассчитывается оценка:

- явная зависимость или конфликт: наивысший вес;
- общая подкатегория: высокий вес;
- общая категория: средний вес;
- общий тип системного объекта или совпадающий объект операции: дополнительный
  вес;
- совпадающие значимые слова названия и краткого описания: дополнительный вес.

Текущая статья и дубликаты исключаются. При равной оценке используется порядок
каталога, чтобы результат был детерминированным. Показывается не более шести
статей. Нажатие открывает статью в той же области и добавляет переход в локальную
историю.

Если подходящих материалов нет, блок не показывается.

## 8. Модели C++

### 8.1 `EncyclopediaTreeModel`

Наследник `QAbstractItemModel`, предоставляющий иерархию категорий,
подкатегорий и статей. Основные роли:

- `nodeType`;
- `id`;
- `title`;
- `summary`;
- `path`;
- `depth`;
- `expanded`;
- `selected`;
- `matchScore`.

Модель принимает поисковую строку, фильтрует листья и сохраняет подходящие
родительские узлы.

### 8.2 `EncyclopediaArticleModel`

Представляет выбранную статью и возвращает QML структурированные секции, а не
готовую разметку. Основные данные:

- идентификатор и заголовок;
- хлебные крошки;
- вводный текст;
- список секций;
- технические сведения;
- совместимость;
- требование перезапуска;
- список связанных статей.

### 8.3 `EncyclopediaController`

Координирует:

- выбор статьи;
- поисковый запрос;
- раскрытие дерева;
- переходы по связанным статьям;
- локальную историю назад/вперёд;
- восстановление корректного выбора после фильтрации.

Контроллер использует существующие каталоги по константной ссылке и не владеет
копией определений.

## 9. Компоненты QML

Предполагаемая структура:

```text
qml/pages/TweakopediaPage.qml
qml/components/EncyclopediaTree.qml
qml/components/ArticleReader.qml
qml/components/ArticleSection.qml
qml/components/ArticleContents.qml
qml/components/RelatedArticleCard.qml
```

Компоненты используют существующие цвета, размеры, радиусы, иконки и состояния
наведения приложения. Новая независимая тема не создаётся.

## 10. Состояния интерфейса

- **Загрузка:** индикатор внутри области страницы без блокировки основной
  навигации.
- **Начальный экран:** дерево раскрыто до категорий, справа — краткое приглашение
  выбрать тему или воспользоваться поиском.
- **Ничего не найдено:** запрос остаётся видимым, показывается понятное сообщение
  и кнопка очистки поиска.
- **Статья выбрана:** дерево подсвечивает статью и раскрывает её путь.
- **Неизвестный ID:** выбор сбрасывается, показывается начальный экран.
- **Неполные данные:** отображаются только заполненные секции.

## 11. Доступность и управление

- дерево, поиск, содержание и связанные карточки доступны с клавиатуры;
- у интерактивных элементов есть состояния наведения, фокуса и нажатия;
- `Enter` открывает выбранную статью, стрелки перемещают фокус по дереву;
- экранные дикторы получают тип узла, название и состояние раскрытия;
- цвет не является единственным признаком выделения;
- длинные названия сокращаются только в дереве, полный текст доступен во
  всплывающей подсказке.

## 12. Изменения существующего интерфейса

- пункт «Справочник» переименовывается в «Твикопедия»;
- информационный символ пункта заменяется иконкой открытой книги;
- `PlaceholderPage` для этого пункта удаляется из маршрута;
- экран «Твики», очередь и боковая справка карточек не меняют поведение;
- клик по статье не добавляет твик в очередь.

## 13. Проверки

### C++

- построение полной трёхуровневой иерархии;
- отсутствие потерянных и повторяющихся статей;
- сохранение родительских узлов при фильтрации;
- ранжирование поиска;
- поиск по русскому тексту, ID и техническому объекту;
- вычисление связей, исключение текущей статьи и дубликатов;
- детерминированный порядок связанных статей;
- история назад/вперёд без повторных соседних записей;
- формирование статьи с пропущенными необязательными полями.

### QML

- пункт навигации называется «Твикопедия»;
- выбор дерева открывает правильную статью;
- отсутствующие секции скрыты;
- содержание прокручивает к нужному блоку;
- связанные карточки открывают другую статью;
- пустой поиск показывает отдельное состояние;
- дерево и содержание корректно сворачиваются на действующих брейкпоинтах.

### Регрессия

- загрузка всего YAML-каталога;
- каталог твиков и очередь продолжают использовать те же определения;
- packaged single EXE содержит новые QML-компоненты;
- приложение запускается без внешнего контента и сетевого соединения.

## 14. Критерии готовности

Раздел считается реализованным, когда:

- все загруженные твики представлены статьями;
- поиск находит статьи по пользовательскому и техническому тексту;
- дерево не показывает пустых ветвей после фильтрации;
- статья автоматически строится из YAML и не содержит пустых заголовков;
- связанные статьи вычисляются без ручного списка;
- навигация назад и вперёд работает внутри раздела;
- широкая и узкая компоновки не обрезают содержимое;
- автоматические проверки проходят;
- собранный единый EXE проходит проверку запуска.

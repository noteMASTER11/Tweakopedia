# Диагностика сети — спецификация

## Назначение

Третья карточка раздела «Инструменты» выполняет диагностический аудит сетевой
конфигурации Windows без внесения изменений. Пользователь видит ход выполнения,
сырой вывод команд и отдельные результаты по каждому проверенному блоку.

Инструмент не запускает сторонний `NetworkCleaner_v2.1.exe` и не переносит его
WPF-интерфейс. Из исходного проекта переиспользуется предметная область проверок;
исполнение остаётся частью Tweakopedia.

## Границы первой версии

Проверяются шесть блоков:

1. сетевые адаптеры, адреса, шлюзы и состояние подключения;
2. назначенные DNS-серверы и разрешение контрольного доменного имени;
3. пользовательский, PAC и WinHTTP-прокси;
4. активные нестандартные строки файла `hosts`;
5. маршруты по умолчанию и постоянные IPv4-маршруты;
6. профили Windows Firewall и активные пользовательские входящие разрешения.

Проверка только читает состояние. Доступные действия относятся к конкретному
результату и открываются в его боковой панели. Общего отдельного инструмента
сброса сетевых параметров нет.

## Пользовательский сценарий

Начальный экран содержит заголовок, краткое объяснение и кнопку «Начать
диагностику». После нажатия Tweakopedia запрашивает повышение прав и запускает
фиксированный сценарий Windows PowerShell 5.1.

Во время работы экран показывает текущий этап, неопределённый индикатор и живой
вывод. После завершения появляются:

- общий итог;
- счётчики «Без замечаний», «Требует внимания» и «Не удалось проверить»;
- шесть карточек результатов с названием, состоянием, кратким итогом и деталями;
- кнопки копирования вывода и открытия журнала;
- при наличии замечаний — кнопка «Открыть отмеченный пункт», открывающая
  подробности первого результата, требующего внимания.

Повторный запуск полностью заменяет прошлый результат.

## Состояния результата

Каждая проверка имеет одно из состояний:

- `ok` — отклонений не найдено;
- `attention` — обнаружена конфигурация, которую следует проверить вручную;
- `unavailable` — конкретную проверку выполнить не удалось.

Общий результат:

- `healthy`, если все доступные проверки имеют `ok`;
- `issues_found`, если есть хотя бы одно `attention`;
- `incomplete`, если нет `attention`, но есть `unavailable`;
- `failed`, если PowerShell не запустился, завершился аварийно или не вернул ни
  одного структурированного результата.

Наличие прокси, записей `hosts`, нескольких шлюзов или пользовательских правил
не объявляется неисправностью автоматически: такие элементы получают состояние
`attention` и показываются пользователю.

## Исполнение

В протокол системных инструментов добавляются:

- `SystemToolKind::NetworkDiagnostics`;
- `SystemToolOperation::Diagnose`;
- этапы для шести диагностических блоков;
- объект `details` в `SystemToolResult`.

Executor запускает только `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe`
с фиксированными параметрами `-NoLogo -NoProfile -NonInteractive
-ExecutionPolicy Bypass -EncodedCommand`. Сценарий встроен в приложение и не
принимает пользовательские строки.

Сценарий принудительно устанавливает UTF-8 для стандартного вывода. Обычные
строки отправляются в терминальную область. Машиночитаемые строки имеют префикс
`@@TWEAKOPEDIA@@` и компактный JSON; workflow отфильтровывает их из терминала,
валидирует и собирает итоговый массив `checks`.

Журнал сохраняет исходные байты в
`Logs/Tools/NetworkDiagnostics/<дата>_diagnose.log`. Экранный буфер ограничен
2 МиБ.

## Структура `details`

```json
{
  "checks": [
    {
      "id": "dns",
      "title": "DNS",
      "status": "ok",
      "summary": "Разрешение имён работает",
      "details": ["Ethernet: 192.168.1.1"]
    }
  ],
  "ok_count": 1,
  "attention_count": 0,
  "unavailable_count": 0
}
```

Workflow принимает только известные идентификаторы и состояния, ограничивает
длину строк и число деталей. Неизвестные маркеры игнорируются как служебный
мусор и не попадают в визуальный итог.

## UI

`NetworkDiagnosticsPage.qml` следует компоновке DISM/CHKDSK:

1. заголовок и Fluent-кнопка возврата;
2. карточка общего состояния и основная кнопка;
3. адаптивная сетка результатов — две колонки при широком окне, одна при узком;
4. терминальная область с автопрокруткой, копированием и открытием журнала.

Карточки результата имеют одинаковую высоту внутри строки. Состояние обозначается
иконкой, цветом и текстом, поэтому цвет не является единственным сигналом.

## Ошибки и ограничения

- Отсутствие интернета может дать замечание DNS, но остальные локальные проверки
  продолжаются.
- Ошибка одного PowerShell cmdlet создаёт `unavailable` только для его блока.
- Отмена UAC возвращает экран в исходное состояние с пояснением.
- Одновременно может выполняться только один системный инструмент.
- Максимальная длительность подчиняется существующему watchdog системной сессии.

## Проверка реализации

- round-trip протокола с `details` и отклонение неверных комбинаций;
- точная команда PowerShell без входных параметров;
- UTF-8, разбиение JSON-маркеров между порциями, фильтрация маркеров из терминала;
- сопоставление итогов и обработка частично недоступных проверок;
- состояния контроллера, ограничение буфера и изоляция событий чужого запроса;
- QML-маршрут, адаптивная сетка, кнопки и пустое/занятое/итоговое состояния;
- IPC fixture, полный CTest и проверка единого EXE.
